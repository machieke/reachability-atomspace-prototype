# Read-only obligation-to-work bridge

```sh
uv run --no-project python -m work_bridge_lab.compare run --output artifacts/work-bridge-local
uv run --no-project python -m work_bridge_lab.compare audit artifacts/work-bridge-local
```

Use a fresh directory and the existing pinned native build. Six controlled finite
sequences and two native reconstructions run without a controller. The harness
supplies actual admitted events and selected existing certified formulas; projection
only reads inputs. Later events are not consequences of its suggestions.

Task roles and six sequences were committed before evaluation in
`reviews/obligation-work-bridge-v1/task.json` and `PROTOCOL.md`. This is one synthetic
owner declaration with explicit test variants, not a default acceptance policy.
The author label/hash is not authentication. All old A/B semantics stay frozen.

Acquisition locks the existing authority, captures its complete numerical view,
reads current registry records and public numeric Probe descriptors, and reads
actual lifecycle/goal state. Internal nonmutation fingerprints are diagnostic
receipts, not semantic snapshot identity: heap serialization can change across
SQLite reopen while all authoritative/public records stay identical. WorkInput
is detached canonical JSON. Observations bind to this exact capture; a separate
inventory digest changes with rule/model/probe records. No new registry is added.

The projector verifies supplied A/B against the frozen evaluators, retaining every
record, objection and unclassified source. Obligations use semantic task/contract
keys independent of reads, paths or witness counts. Eligible producer routes form
OR alternatives; each exact ordered method tuple retains all AND prerequisites.
One operation may be referenced by several obligations. No scalar demand/pressure
or observed loss is computed from node counts.

Only a single producer step and direct observation routes for its missing premises
are supported. Deeper registered inference routes are explicitly incomplete.
Missing exact revision parents cannot be silently replaced by an equal-valued new
report. All existing registered relevant producers remain investigation records,
even if no declared role matches or positive obligations already have witnesses.
This is not exhaustive counterevidence discovery or a stochastic plan.

Numeric observation descriptors give public source/target opportunities; actual
lineage and admitted numerical results still determine applicability. Unknown
availability and declared observation preconditions remain explicit. Product/health
channels are listed as unsupported by this bridge. Lifecycle/outcome requirements
are actual read-only state, never computed from a numerical PASS.

There is no ordering policy: sorting is deterministic presentation. Already
materialized method tuples are marked RESULT_ALREADY_RECORDED and never presented
as a way to fix inadequacy through repetition. Input presence is not certification
or guaranteed adequacy. Live A blocks and A/B disagreement stay explicit. Work
objects are rejected by typed live permission/registration APIs.

Bounds cover input bytes, inventory, current premises, tuple visits, operations,
nodes, edges and role comparisons. Incomplete, malformed, scope-mismatched or
exhausted views expose SCOPE_OR_BUDGET_INCOMPLETE; partial nodes are diagnostic.
Complete describes explanation coverage, not an executable task or successful goal.
Capture assumes trusted local authoritative data; it is not JSON authentication.

Timings charge full capture/public-model acquisition, initial frozen evaluation,
frozen revalidation, discovery/graph building and serialization. Counts include
acquired records, current premises, tuple visits, history scans, comparisons,
operations, nodes, edges and output bytes. Stage counters are nested in inclusive
totals. No scalable index, speed advantage or autonomous repair is claimed.

Applicable regression inventories, omitted coverage, raw inputs, exact native
outputs, development failures and source bindings are in the review publication.
Stop after this conformance integration; live policy, controllers, transport,
recovery, numerical formulas and native storage remain unchanged.
