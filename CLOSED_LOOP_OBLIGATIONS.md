# Experimental closed-loop assessment consumer

`experimental_work_loop.consumer` consumes a coherent current public snapshot and
frozen obligation work view. It chooses exact existing public candidates using
first-ready FIFO within declared control, adoption, graph-work and authorization
classes. B imposes the declared research-task work requirements; existing A and
all live hard gates remain authoritative. This changes experimental scheduling,
not acceptance semantics or the frozen bridge.

`observe` acquires the full capture and public inventory under the service lock,
evaluates frozen A/B and invokes the frozen bridge. `Consumer.choose` cannot access
the session, environment, expected choices or future reports. It maps exact producer
records and complete ordered tuples, or exact probe source/target/opportunity/cost,
to members of the existing complete public frontier. `execute_current` rechecks
that frontier immediately and invokes the original session freshness/membership,
precertificate, inference, postcertificate and commit interfaces.

All current registered one-step producers of the criterion/opposite are required
finite review, including already satisfied obligations' investigations. All current
tuples must have current materialized results; a failed attempt is unresolved.
New producers/tuples invalidate review closure. Relevant raw reports are adopted
without inspecting numerical favorability or root eligibility. A raw report is
never counted as a witness. Failed/unadoptable reports keep review open. Optional
unrelated producers remain in the public frontier and the unexamined inventory.
No deeper backward chaining or inference closure is claimed.

The ephemeral agenda uses existing relevant-basis/opportunity keys. Shared graph
references select one actual candidate. Unrelated refreshes never create retries.
The numeric queue reserves eight selection/work credits and four acquisition
credits for existing control/monitoring. Total budgets are still enforced.
No restart/resume ledger or retry of ambiguous external effects is added.

Accepted/uncertain actions retain their existing reconciliation and product/health
obligations, even under an incomplete graph or later numerical block. These use
existing coordinator channels, which remain unsupported by the frozen graph.
Observed completion requires the existing product, health durability and lifecycle
APIs. Positive numerical values, requests and acknowledgments cannot reduce loss.

Run the committed finite/native cohort into a fresh directory:

```sh
uv run --no-project python -m work_loop_lab.compare run --output artifacts/work-loop-local
uv run --no-project python -m work_loop_lab.compare audit artifacts/work-loop-local
```

Requires the existing pinned build documented in NATIVE_RECALL.md. Native absence
is a blocked run, never a finite substitution. Six synthetic parents × two formula
modes are repeated configurations, not twelve independent tasks. Controlled source
responses model acquisition; the controller selects each core operation itself.
Related wrong-product, health, uncertainty, applicability and freshness boundary
continuations are focused tests, not new cohort tasks.

See `reviews/closed-loop-obligations-v1/` for declarations, the selector-identity
correction, immutable review, omitted coverage, failures and measured costs.
Stop after bounded conformance publication. No policy promotion, comparative
scheduler claim, pressure/transport, generalized recovery or storage expansion.
