# Goal-directed online PLN discovery v1 — preregistration

Frozen baseline: publication 3f433ed; measured 0cd1f8a. Existing source, twelve
fixtures, corrections and reviews remain unchanged. This is one bounded experiment.

The question is whether directed dependencies avoid irrelevant work without losing
relevant candidates or changing authority. Exactly three arms: frozen FIFO-full;
Goal-scan (full enumeration, task preference); Goal-index (cold maps, scoped tuple
enumeration, identical task preference). Goal arms use first-ready FIFO and frozen
semantic ties, with no value/pressure/strength/depth ranking. Only eligible,
affordable relevant work precedes background. Background receives age only upon
shared full fallback; relevant ages accumulate equally. No eligible affordable
relevant work triggers bounded full fallback, explicitly logged. Incomplete
closure also triggers full fallback, never a false completeness claim. Frozen
execution membership revalidation remains full enumeration and is charged.

Task roots derive from actual registered decision, execution, lifecycle, completion
and goal contracts, including both criterion polarities and monitoring. Directed
closure retains every producer and all five ordered requirements; AND/OR contract
structure stays inspectable. A canonical shortest path witnesses each retained
literal; multiple paths do not mint obligations. All-current admission reads the
whole authority. Roots/indices never admit reports, run formulas or authorize work.
Closure bounds: 128 nodes, 256 premise edges, depth 16. Existing coordinator bounds
remain rules 16, estimates 32, candidates 64, tuple visits 128, selections 32,
acquisitions 16. Work budgets 8 and 16. Incomplete scopes are explicit. No persistent
index or native retrieval claim. Unsupported hard-fact acquisition is not invented.

Twelve new parents (fixtures.json), three per family, seed 0; each runs both budgets,
all three arms, finite and pinned native: 144 executions, twelve independent designs.

* Selection: one ready deduction control; two unrelated ready deductions competing
  with missing relevant evidence; shared-input distractor with unrelated output.
* Composition: a two-deduction chain; a three-deduction chain; two alternative
  producers with an alternative current support tuple. Chains have a missing leaf
  acquired through a public probe. No desired-answer primitive. Numerical base
  marginals .5, conditional strengths .8, confidence .95; single-route/control
  uses the existing valid (.4,.5,.6,.7,.8), confidence .8. Existing .65 strength /
  .35 confidence decision gate remains unchanged. Multi-hop confidence may block.
* Changes: equal-valued premise replacement after proposal before postcheck;
  producer insertion at the same explicitly labelled proposal boundary, with old
  producer revision changed to another output; unavailable source plus a current
  direct contrary estimate and a received low-confidence unfavorable report.
  Boundary injections are distinct from exogenous world events. No nth-action
  event claims. Failed/stale attempts consume work.
* Lifecycle: already supported forecast needing product; already supported forecast
  with product observed and monitoring pending; supported forecast with durable
  completion followed by a declared continuing-monitor boundary (tick 4, unhealthy
  observation). This last is explicitly a completion boundary injection, not an
  exogenous clock schedule. All preserve unmet operational demand.

The local world advances to tick 1 on accepted dispatch and product availability;
health samples are opportunities at ticks 1,2,3; completing a request exposes the
next declared opportunity. This received-event clock measures ordering/work, not
real elapsed sensor benefit. Numeric availability is fixed privately at setup;
no deadline promises or future responses enter controller inputs. Fixtures never
select actions. Physical sensor/network latency is unmeasured. No cohort tuning
for advantage. Rename/reorder siblings are diagnostics, not additional parents.

Primary cases stay within all global caps; overflow/cycle/depth/tuple stresses are
separate tests. Local three-proposition joint checking does not establish a global
joint model over composed estimates. Finite/native semantic parity, independent
scan/index replay, invariant tests, four negative mutations and native projection/
readback are required. A correctly blocked case is not successful deployment.

Record public snapshots, roots, closure, witnesses, exact candidates, choices,
receipts, actual selected formulas, work landmarks, goal/external losses and stops.
Charge full reads and serialization, root extraction, closure, cold index creation,
candidate/tuple construction, ranking, full fallback and full execution revalidation,
admission/commit persistence, acquisition, dispatch/monitoring and episode time.
Nested inclusive costs are not additive. Report actual index entry counts, not
unmeasured RSS. All native startup/checking is included in call timings; SQL/fsync
and native compute separately from startup remain unmeasured. No wall cap arm.

Source-bound publication uses existing seal/archive helpers and fresh output.
Applicable suites and exact revisions are listed; historical full-suite passes are
not this increment's passes. Preserve development failures and corrections. Stop
on tested and published implementation regardless of performance direction.
