# Codex handoff: connect native AtomSpace recall to the multi-hop work loop

## Decision and baseline

Close the bounded multi-hop milestone at publication `c4686bc`. Preserve measured implementation/auditor `b509d2b8d7388a570b5a666e1c845b95d207ad20`, review publication `626c06e868a41ffb7e8b3dcdb3bb21577a94a22f`, preregistration `0d7fba14937d88a69813dc94d511c57d504a2440`, and previous sources, reviews, failures, corrections, coverage, and native build receipts.

**Next milestone: native AtomSpace-backed discovery for the existing bounded multi-hop controller, with semantic parity against the frozen scan implementation.**

This is an integration of existing capabilities, not another attention algorithm. The repository already has genuine native recall in a separate experiment, and it now has certified online numerical chains of depth two and three. The current multi-hop projector, however, obtains producer and support membership by scanning the captured Python records. Connect that discovery boundary to the existing native query backend.

Do not increase inference depth, add another producer family, widen the finite rule language, change numerical thresholds, promote policy B, introduce adaptive transport, or redesign native storage. Do not port the old WS-queue/local/flow scheduler or assembly-protection policy into this loop. The multi-hop consumer's priorities and review contract are the control condition.

This handoff is a proposed implementation and validation plan. It does not report execution of the new experiment.

## 1. Preserve the completed findings

The frozen cohort contains six parent structures in two formula modes. Four parents complete in both modes; unavailable-input and adverse-evidence parents remain unresolved. There are 30 formula calls, including 15 fresh native calls, and exact committed dependency depths of up to three. Shared work has four calls but longest depth three; replacement has three calls but current depth two. These are distinct quantities. [S1, S2]

All successful structures dispatch at logical tick zero and complete at tick three because the differing inference work fits the same eight-operation tick allowance. Their equal physical/recognized loss integrals are not evidence that greater depth is computationally free or that a scheduler improved. [S2]

The latest 548 regression passes comprise 462 applicable default and 86 native tests. Preserve the documented omitted coverage; do not turn historical passes into fresh coverage. [S3]

The new comparison should establish whether actual native query answers can drive the same multi-hop choices and outcomes. Native recall need not be faster to satisfy this integration milestone. It must not be credited with a speedup or bounded-total-memory property merely because a query returns a short list.

## 2. The exact boundary being changed

Today, `experimental_multihop/project.py` builds a producer list from `inventory['rules']`, finds current support alternatives by literal equality over captured estimates, constructs five-slot products, and computes the bounded graph. `experimental_multihop/consumer.py` retains full public-frontier enumeration and exact operation matching before selection. [S4, S5]

Keep the latter's policy and authority behavior. Change how the multi-hop work graph obtains its discovery records.

The new path should be:

```text
Complete coherent public capture
        |                         |
        |                         +--> Frozen assessment and authority checks
        v
Existing complete immutable native AtomSpace view
        v
Actual typed native query answers
        v
Bounded producer closure and complete exact tuples in Python
        v
The same multi-hop work-view semantics and consumer policy
        v
Existing full-frontier membership checks and certified execution
        v
Actual PLN result; new exact committed revision
        v
Fresh correctly bound view; downstream native lookup and inference
        v
Unchanged physical world and admitted-observation completion
```

Python may continue traversal, tuple assembly, scope accounting, FIFO selection, decoding, and orchestration. This milestone does not require Atomese to implement a planner or C++ to perform the full reasoning process. The native query must determine which records answer the producer/support question.

## 3. Reuse the pinned native query backend

Use the existing `experimental_native_recall` schema, backend, build receipt, and helper. The documented query vocabulary already includes `producers`, `current`, `historical`, `reports`, `probes`, `models`, `record`, `all_rules`, and `all_current`. [S6, S7]

The view already represents the full declared source inventory before relevance is computed. It preserves ordered premises, literal polarity and argument order, record identities, numerical values, and full-history/current distinctions. A same-binding view can be queried repeatedly; changed bindings require the existing cold replacement. [S6, S7, S8]

Prefer a small adapter/record-access interface in a separately named experimental module. Keep the measured scanner and original consumer available unchanged. A thin wrapper can provide the existing typed work view to the original consumer; do not fork its policy if that is unnecessary.

Do not change the C++ query protocol or native build merely to implement another traversal. If a concrete necessary capability is missing, document the exact gap first. Do not silently replace it with a Python answer and call the run native-complete. A missing capability is a bounded result, not authorization for a storage redesign.

### Suggested access responsibilities

- Producer lookup for each demanded literal, including the criterion and its opposite.
- Current-support lookup for every ordered premise and materialized conclusion.
- Registered observation/report discovery for missing or pending evidence.
- Exact history/ancestor retrieval needed to validate depth and provenance.
- Existing model/scope checks needed to retain unsupported relevant revision routes.

These are responsibilities, not mandatory new API names. Use existing typed query forms.

An exact source-ID decoding map may resolve native-returned identities to their immutable records. It must not select which identities match a query. Do not iterate that map as a parallel answer index for native discovery. If ancestor IDs are known from an already retrieved record, fetching those exact records is legitimate; guessing uncomputed intermediate IDs is not.

## 4. No Python answer substitution

Separate three activities explicitly:

1. **Capture, validation, and projection loading:** full source records are available and may be inspected as required by the unchanged contracts.
2. **Discovery membership in the native arm:** producers, relevant supports, and observation records must be obtained from actual query responses.
3. **Execution revalidation:** the existing full public frontier and authority independently check the selected operation.

Do not run the frozen scanner, take its completed graph or candidate identities, and then query AtomSpace only to confirm those answers. That would be a verification wrapper, not native-driven discovery.

The current projector reuses the one-step projector for validation as well as graph work. A native adapter may reuse its validation outcome, but cannot copy its computed producer routes or applications as native-discovered answers. Either preserve and fully charge the unused reference calculation, or introduce a minimal separately named validation adapter with explicit parity tests. Do not rewrite the frozen one-step implementation or its meaning.

Full-frontier enumeration used by the unchanged consumer can remain as an independent matching/revalidation boundary. It must not repair missing native graph nodes, invent a missing dependency, or convert an incomplete native work view into a complete one. Its overhead remains part of total cost. The milestone does not eliminate all full-state scans from the overall system.

The offline scanner/reference may compare every native result and graph after the run. Reference answers must not be supplied to the controller.

## 5. Preserve semantic completeness and exact binding

Keep the registered-depth-three review unchanged:

- Include every registered producer of the criterion and its opposite within the declared closure, with complete upstream requirements.
- Keep symbolic producer templates separate from concrete exact applications and actual committed results.
- Query every required premise slot, retaining order and all current alternatives needed by the frozen semantics.
- An existing favorable result cannot conceal another registered producer or an adverse estimate.
- A cycle, deeper route, unsupported relevant model, partial inventory, or exhausted bound remains explicit and incomplete.
- Retired estimates remain historical; they are not current premises.
- A shared intermediate is one record referenced by multiple applications, not extra independent evidence.

The native view and all responses must match the current authority/context/snapshot/build binding. A commit, revocation, changed relevant rule, received report, or other changed snapshot binding uses the existing view-replacement discipline. No mixing producer information from one epoch with supports from another.

Full A/B evaluation and live authorization continue to inspect their complete relevant authoritative scope. A narrow native query is not a narrow acceptance boundary. The new adapter supplies neither execution authority nor a completeness theorem about all possible inferences.

Native query receipts are provenance of retrieval, not certificates. The pinned helper and load/readback checks retain their present trust assumptions; do not invent a cryptographic guarantee against arbitrary malicious result omission.

## 6. Do not conflate empty, incomplete, and failed queries

Retain these meanings:

```text
Complete empty answer:
    No matching record in this exact declared view.

Complete nonempty answer:
    These records answer the query in this view.

Explicitly incomplete answer:
    A bound prevented a complete answer; absence is not established.

Stale, invalid, or failed native view:
    The response cannot be used as current discovery.
```

For the new native multi-hop arm, no silent or successful full-scan fallback may populate the work graph. Older experiments' fallback behavior stays unchanged. In the new arm, bounds or native failure must be visible and prevent a newly authorized action that depends on incomplete review.

Already accepted/uncertain external operations still need reconciliation and monitoring. Their existing public control path must not be disabled merely because a new numerical discovery view is unavailable. Use the same operational priority and headroom; do not reset task budgets or attempted-work identities.

Helper termination or timeout tests may invoke existing close/rebuild behavior explicitly. Do not add restart automation, durable native state, or a recovery service.

## 7. Comparison: two retrieval arms, unchanged task policy

Use:

- **MH-scan:** the frozen multi-hop path at `b509d2b`.
- **MH-native:** native-backed work discovery, with the same review, consumer, formula, authority, and world semantics.

Cross those two arms with the existing finite-checker/native-PLN formula modes. Native recall must be genuinely native in MH-native even when formula arithmetic uses the finite checker.

Reuse the same six registered parent fixtures and budgets: 24 core executions. These remain six parents, not a new generalization sample. Do not tune fixture probabilities, source roles, observation timing, or thresholds.

At matched snapshots and identical consumer history, compare:

- Relevant producer identities and full declared review coverage.
- Complete ordered premise alternatives and materialized-result status.
- Relevant observation/report routes and unresolved reasons.
- Actual depth, ancestry, shared dependencies, objections, and review completeness.
- Eligible candidates, exact premise bindings, priority/age ordering, selected operation, and stop reason.
- Operation/work/acquisition budget history.

Native transport metadata, process-local handles, query logs, and timing may differ. Compare semantic fields and stable application IDs rather than requiring identical raw payload bytes where backend-specific metadata is intentionally added. Prefer the same work-view schema for semantic data when possible.

Then run each arm closed-loop. In the supported nonexhausted fragment, selected numerical work, physical command sequence, and recognized outcomes should match. A discrepancy is a conformance defect to investigate, not a performance win. Preserve failed runs and corrections.

No additional scheduler arm, pressure policy, memory-capacity sweep, or million-atom scale sweep belongs in this increment.

## 8. Targeted boundary tests

Reuse the current structural, formula, provenance, world, and native-reference tools. Add only tests for the integration seam:

1. **Native queries are causally used.** A test-local guard forbids scanner answer production in the native discovery path while legitimate source loading and independent authority checks still work. Interrupting or making a required native response explicitly incomplete must not leave an apparently successful scanner-backed graph.
2. **Intermediate round trip.** The first selected native deduction commits a new intermediate; a correctly rebound native view returns that exact intermediate as current; a subsequent selected deduction consumes it. No fixture supplies the intermediate.
3. **Revocation/replacement.** Retired intermediate and descendants remain historical; new exact inputs require new view/bindings and recomputation. Equal numbers do not revive an old intent.
4. **Registry insertion.** A newly registered relevant producer becomes visible on the new view even when it was absent from previous dependency lists. A required adverse producer cannot disappear through cached absence.
5. **Complete AND and shared work.** Missing slots cannot yield a candidate; shared records retain one identity and original ancestry.
6. **Opposite evidence and weak alternatives.** Selective discovery cannot bypass A/B or contrary-evidence inspection.
7. **Query limits and helper failure.** Explicit result/visit/query exhaustion, malformed readback, stale epoch, and helper loss remain distinguishable from complete empty answers. No hidden scan fallback or budget reset.
8. **Typed transport.** Preserve ordered arguments/polarity, ordered five-premise rules, and exact integer metadata; reuse existing native tests where already covered.
9. **Declared fragment.** Depth-four and cyclic-route diagnostics stay incomplete even if a favorable current estimate exists.
10. **Review/execution separation.** A native-complete work graph does not authorize execution; unchanged gates must reject stale or otherwise inadmissible requests.

For a forged response falsely claiming completeness, distinguish what runtime validation can detect from what the independent audit detects. Do not claim that each arbitrary semantic omission is cryptographically detectable by the runtime.

Use a few targeted unrelated records within the existing caps to ensure retrieval is not fixture-name dependent and contrary relevant records are not classified as irrelevant. This is a membership test, not a scaling study.

## 9. Cost and memory accounting

Report the full path and the unchanged remaining scans:

- Coherent public/authority capture and export sizes.
- A/B evaluation and scope/history validation.
- Native projection construction, serialization, build checks, startup, load, and readback.
- Number of view epochs, replacements, exact-binding reuses, and their costs.
- Actual typed queries, relation visits, result counts, bytes, and per-query reasons.
- Python traversal, tuple products, serialization, candidate selection, and full execution-frontier revalidation.
- Native/finite formula calls, certification, commits, persistence, dispatch, observations, and total episode time.

Keep nested timers explicitly nested; do not sum overlapping totals. Reuse current instrumentation. Timing is descriptive unless an independently declared timing experiment is added later.

Measure or explicitly leave unmeasured RSS, peak memory, serialization copies, and native process memory. Loading the whole snapshot into a native view does not bound total memory by the returned working set. Do not claim persistent or distributed AtomSpace authority: SQLite remains authoritative.

An unchanged-binding repeated-query diagnostic can demonstrate reuse. It is not a realistic warm-workload result. A chain whose every commit causes a cold rebuild must pay that cost. Do not add incremental synchronization to improve the comparison.

The independent-world clock, operation slots, and observation timing stay unchanged. Greater wall-clock overhead may not change the logical outcome in this simulator. State that distinction; no real-time or cognitive-speed claim follows from semantic parity.

## 10. Validation, publication, and stop

Run the applicable native-recall, multihop, bridge/consumer, numerical-ledger, decision, lifecycle, and independent-world tests plus focused new tests. Exact executed/omitted coverage must be recorded at the measured revision. Missing native dependencies block the relevant requirement; finite arithmetic is not a substitute for native recall or native formula execution.

Reuse the existing immutable-source archive, query checker, replay, mutation, and publication machinery. Native query reexecution, recorded-formula checking, fresh PLN invocation, and SQLite reconstruction are distinct audit activities; label their counters accordingly.

Publish one review bundle with source/build/configuration identities, semantic parity results, raw native receipts, exact selected inputs and intermediate ancestry, real authority/world outcomes, all costs, failures, corrections, and omissions. Provide one command for the 24-run comparison and an audit command using a fresh output directory.

**Stop when the existing bounded multi-hop behavior can be driven by native retrieval with the declared parity and failure semantics, and one source-bound result is published.** A slower native path may still complete the integration milestone. Do not promote it as faster, more capable, or safer than the same frozen policy.

Do not proceed automatically to adaptive transport, working-set scheduling, persistent or incremental native storage, more depth, larger scans, a generalized benchmark, new decision policy, calibration, evidence supersession, generalized recovery, or another optimization round. Those require separate choices informed by the measured integration.
