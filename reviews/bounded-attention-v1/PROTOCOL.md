# Bounded working memory and fixed gated transport v1

Freeze publication 77e30ef and its measured/auditor source 79f4f43. New modules only;
no changes to previous controllers, native helper/build verification/lifetime,
formulas, source fixtures, authority, admission, execution or recovery semantics.

One native-query-driven controller has WS-queue, WS-local and WS-flow modes. The
last two share root seeding (0.8 of B=1, uniformly among canonical numeric and
product/health inspection roots), new anchors at zero, and 5% cooling after each
expansion. Seed event IDs are unique within a complete snapshot epoch. WS-flow
alone performs four uniform-rate gated conservative microsteps before each job.
Queue mode uses FIFO jobs. Activation modes use descending anchor allocation then
FIFO sequence. Final operations use identical first-discovery FIFO and existing
semantic ties. Allocation never ranks operations or constitutes proof.

Operational anchors are scoped literal inspection, exact producer operations and
public observation opportunities. Routes are target→producer→ordered premise
inspection, and target→probe inspection→request-use. Missing premises are readable;
explicitly unavailable probes and unmet operation/product preconditions close the
use route. Only current PASS opens a route; direction/purpose/context/binding are
checked. No arbitrary native ListLink diffusion. Wrapper syntax is not a route.

Declared active settings are bundle24 and bundle48: 24/48 entries (anchors and
records together), 256/512 KiB exact encoded payload accounting. A five-premise
operation requires a rule, up to five distinct supports, its candidate descriptor
and control pins; both settings fit a normal such bundle. Shared task structure can
exceed these limits. Shared LRU removes only unpinned working copies. Selected
exact tuples remain pinned through execution, then release. Control ledger cap 8
and 64 KiB; its entries count against active capacity. Overflow is explicit.

Query budgets q16/q48 permit 16/48 actual typed native calls per decision and at
most that amount times 33 per episode (32 selection bound plus terminal read).
Native results: 32 records/256 KiB per response, visits 4096, queries/view 4096.
Jobs/completeness metadata: 128 jobs/64 KiB, 256 cached result IDs/64 KiB. Arcs: 128;
candidates: 16/64 KiB; joint buffer: 32 distinct records/256 KiB and 256 slot IDs.
Tuple visits: 128 per decision. Field steps: four per expansion, at most 4096 per
decision and 135168 per episode. All are separate counters, not activation units.

Interleaving: service live control obligations first using the same fixed bounded
ledger in all modes; discover up to the query tranche, then rank complete retained
candidates. Join jobs require six query credits (five ordered slots and conclusion
for exact duplicate suppression) before starting. Missing candidates after exhaustion
produce BOUNDED_SEARCH_UNKNOWN. No full Python discovery rescue in primary trials.
A named bounded-stop policy replaces full background fallback equally for all new
modes; observations/uncertain-attempt resolution remain schedulable before search.
Work budget 16, acquisitions 16, selections 32 are shared. Attempts/ages/counters
survive workspace rebuilds. Whole snapshot changes invalidate all overlay permits,
completeness and candidates. Microsteps do not change knowledge or native epochs.

Premeasurement accounting clarification: arc payloads are also capped at 64 KiB
(256 KiB in complete mode). Public root descriptors are capped at 64 roots/64 KiB;
diagnostic identity history at 2048 seen IDs within the metadata byte cap; retained
episode ages at 8192 IDs/4 MiB, attempts bounded by 32 selections. Per-decision
event recording has 8192 events/8 MiB. There are at most 33 decision tranches.
Interrupted jobs remain partly explored even if no queued jobs remain. These
auxiliary caps were made explicit before outcome comparison; primary active/query
settings, seeding, ranking, stopping and parent cases are unchanged.
